# Manual verification checklist

Host code (lib/) reloads live with `plugin_manager set_plugin include:linked-workspace-ui`; client changes load with **应用 → 重新加载界面** (a full restart is only needed after re-installing the package). Then verify:

## 主机密钥与输出编码（0.20.0）

1. 设置 → 联动工作区 → 「SSH 主机密钥与输出编码」应能看到「主机密钥策略」（tofu / strict）、「远端命令输出编码」（utf8 / gbk），以及已记住的主机列表（每行显示 `host:port` 与 `SHA256:…` 指纹）。
2. 把策略切到 strict，在「忘记」某个主机的密钥后再点该主机的工作区：目录树应报「Host key … is not known yet」，HTTP 409，且不会悄悄重新记住。
3. 切回 tofu 再刷新：连接恢复，密钥重新出现在列表里。
4. 把输出编码切到 gbk，用 `hosts.exec` 让中文 Windows 远端输出中文，应正常显示；切回 utf8 应变成乱码（说明不是被强行转码）。

## 本地改动推回远端（0.19.0）

1. 在联动工作区的**本地**目录里改一个文件、新建一个文件，然后点目录栏的同步按钮：差异预览里能看到「新增 1 · 修改 1」，并列出这两个文件。
2. 点「推送（跳过冲突）」后提示「已推送 N 个文件」，远端目录刷新后能看到新内容（`ssh … cat` 核对）。
3. 在**远端**改同一个文件、本地再改一次，重新打开差异预览：该文件出现在「冲突」里；点「推送（跳过冲突）」后远端内容保持不变，提示里带「1 个冲突未处理」；点「推送并覆盖冲突」才会用本地版本覆盖。
4. 在行菜单上对某个远端文件点「把这个推送到远端」：差异预览只包含该文件。
5. 设置 → 联动工作区 → 「自动推回远端」：打开开关会先出现黄色说明与「我明白，开启自动推送」，未确认前不会开启；确认后本地保存文件约 1.5 秒后自动出现在远端，同一文件远端也改过时保留远端版本。
6. 断网或 SSH 断开时推送会失败并显示原因，本地文件不受影响。

## @ 引用与搜索增强（0.18.0）

1. 内容搜索栏在「内容」模式下有五枚 chip（`Aa`、`.*`、目录范围、`.*/`、文件图标）与一个「停止」按钮（仅在搜索中、且有 jobId 时出现）。
2. 打开「只列文件名」→ 结果行不再显示命中行与行号，只列文件；打开「包含通常忽略的目录」→ 原本被跳过的 `node_modules`/`.venv`/`dist` 中的文件也会出现（`.git` 始终不出现）。
3. 搜索一段较大的目录时点「停止」→ 请求 `fs.grepCancel { jobId }`，结果提前结束并在 `truncatedReason` 里给出 `cancelled`。
4. 结果上方显示「扫描 N 个文件 · X（跳过 M 个）」，数字来自 `scannedFiles`/`scannedBytes`/`skippedFiles`。
5. 右键任一文件或目录 → 「复制为 @ 引用」→ 剪贴板得到 `@相对路径`（如 `@src/app.py`），提示「已复制 @src/app.py」。
6. `fs.references { linkedId, query: 'a.txt' }` → `{ candidates: [{ relative, name, kind }], scannedEntries }`，完全同名的排最前；`limit` 生效；空 query 返回空候选而不是报错。
7. 模型侧：让它「用 linked_workspace 的 references 动作找一下 xxx 文件」→ 工具卡片按「dir/file + 相对路径」列出候选。
8. 已知限制（需人工确认未变化）：`@` 补全弹窗里不会出现远端路径 —— 宿主 `fileReferences` 服务只有 `list(agent, query, signal)`，没有 provider 注册入口。

## 远端命令执行（0.17.0）

> 注意：本机这套 DSH **Web** 构建里没有可见的设置入口（账号菜单只有「意见反馈 / 退出登录」，`Ctrl+K` 是会话搜索，插件详情页只有「卸载」），所以设置区块的渲染要在**桌面端**确认；Host 侧行为可以直接用下面的 API 命令验证。

1. 设置 → 联动工作区 → 「远端命令执行」：默认总开关关闭、两个白名单为空、超时 60 秒、输出上限 200000；打开开关后才出现黄色警告行与两个白名单列表。
2. 开关关闭时执行：`hosts.exec { linkedId, command: 'echo x' }` → `403 EXEC_DISABLED`，提示里指向设置页路径。
3. 开关打开但主机白名单为空 → `403 EXEC_HOST_NOT_ALLOWED`；把该主机加进白名单 → `echo hi; pwd` 返回 `exitCode: 0`、`stdout` 含 `hi`、`cwd` 等于工作区远端根。
4. 工作区白名单填一个不相干的值 → `403 EXEC_WORKSPACE_NOT_ALLOWED`；留空表示不限制。
5. `command: ''` → `400 BAD_REQUEST`；`cwd: '../..'` → `400 BAD_REQUEST`；`timeoutMs: 1000` 配 `sleep 5` → `504 EXEC_TIMEOUT`。
6. 审计：每次尝试（含被拒绝）都往 `$DSH_HOME/linked-workspace/exec-audit.jsonl` 追加一行 JSON，含 `auditId`、`hostId`、`command`、成功时的 `exitCode`/`durationMs`/`stdoutHead`、失败时的 `refusal`/`message`；文件超过 5 MB 时轮转为 `exec-audit.jsonl.1`；设置页「打开审计日志」用系统默认应用打开它。
7. 模型侧：在联动/远程工作区的会话里让它「用 linked_workspace 的 exec 动作跑 uname -a」→ 工具卡片返回退出码与输出；开关关闭时模型会收到 `EXEC_DISABLED` 与开启指引。
8. 旧 Host：`meta.info` 的 `apiRevision` < 3 时目录树顶部出现「DSH 的插件进程仍在运行旧版代码」横幅。

4. 添加联动工作区：
   - SSH 连接 + 远端目录（浏览），本地目录（浏览/新建文件夹/系统选择器），镜像可选，名称可选；
   - 创建后：本地目录出现 `.local/linked.json`、`.local/session/`；镜像开启时还有 `.remote/`；
   - DSH 左侧工作区列表出现新工作区，标题**不带** `⇄`，行首图标是链环（不是文件夹）；
   - 设置页联动卡片显示本地 ⇄ 远端路径、镜像开关、「同步」。
5. **后台同步**：镜像默认关闭；打开镜像开关后立即开始一次后台检查，之后每约 5 分钟自动检查远端与 `.remote` 的差异（下载变更、删除多余镜像、跳过未变更文件）。点「同步」→ 立即显示「同步中：N 个文件 / X KB」与「取消同步」，超过 60 s 也不会报超时；完成后显示「同步完成：N 个文件」，`.local/mirror-manifest.json` 更新。关闭镜像会取消进行中的任务，两侧允许有差异。
6. 主题模式：默认选中 **系统**（跟随 DSH 浅色/深色）；三张模式卡无预览条；「指定主题」共 9 张家族卡（GitHub/Solarized/One/Dracula/Monokai/Nord/VS Code/Xcode/Catppuccin），每卡同时有浅色/深色版本；切模式卡后同一批卡片预览在浅色/深色间切换，编辑器配色同步。
7. 打开方式：右侧栏工具栏「打开选项菜单」→ 编辑器 / 系统默认应用 / 复制路径；选择后 `settings.get` 返回 `fileOpenMode` 对应值，下一次点击文件按该方式处理。

## 左侧「添加工作区」

1. 点左侧工作区标题栏的「+」→ 弹窗出现「本地工作区 / 联动工作区 / 远程工作区」三个页签。
2. **底部按钮一致**：三个页签的「创建」都应是同一种主按钮外观（不因页签切换而变灰）；本地页签在没填目录时点「创建」→ 表单里出现红色提示「先选择或填写一个本地目录」，填入后提示消失。

4. 联动/远程页签的**远程目录选择器**：底行左边的路径很长时，路径在自身位置省略显示（悬停看完整路径），右边的「+ 新建文件夹」「使用此目录」始终可见；点「新建文件夹」→ 输入名称 → 回车或「创建」→ 远端建好该目录并自动进入；重名会在选择器内提示「远程目录已存在」。

## 本机 SSH 凭据（0.12.0）

1. **没有私钥的主机不再置灰**：在 `~/.ssh/config` 里写一个没有 `IdentityFile` 的 Host（例如 `Host demo` / `HostName 10.9.9.9` / `User dev`），重启后「添加工作区」弹窗里该主机可点选，右侧 chip 显示「需要密码」，主机列表下方出现「SSH 密码」输入框与「密码只保存在本机…不需要安装 SSH Manager 插件」的提示。
2. **保存后立即生效**：填入任意密码点「创建」（远端目录不可达时创建会失败，但凭据已写入）——该主机 chip 变回 `~/.ssh/config`，hint 变「已保存密码。想更换就重新输入，留空则继续使用原密码。」；`$DSH_HOME/linked-workspace/ssh-credentials.json` 出现 `{"version":1,"byHostId":{"sshconfig:demo":{"password":"…"}}}`，权限 `0600`。
2b. **验证密码按钮**：填一个错误密码点「验证密码」→ 输入框下方出现红字「验证失败：SSH 认证失败，请检查主机凭据：… All configured authentication methods failed.」；填对后显示绿色「密码可用，可以继续创建。」。
3. **主机状态跟着变**：`hosts.list` 里该主机 `authType` 从 `agent` 变 `password`、`hasCredential` 与 `hasStoredPassword` 均为 `true`；再连会进入真实网络（错误是连接层面的 `SSH_CONNECT`，而不是「没有密码」）。
4. **清除**：`hosts.credentials` 传 `{ hostId, clear: true }` → 返回 `authType: 'agent'`、`hasCredential: false`，文件里的条目被删掉，弹窗里又显示「需要密码」。
5. **不装 dsh-ssh-tunnel 也照常**：没有 SSH Manager 时上述流程全部可用；`identityFile` 与 agent 的主机行为不变，仍显示 `~/.ssh/config`。
6. **不影响已有的密钥主机**：`~/.ssh/config` 里带 `IdentityFile` 的主机 `authType` 仍是 `privateKey`、`hasCredential` 仍为 `true`。
7. **弹窗内滚轮只滚弹窗**：主机多到出现滚动条时（≥6 台），把鼠标放在 SSH 主机列表上滚动滚轮 → 列表先滚；到底后继续滚 → 表单滚；全程背后会话区域不滚动。鼠标放到弹窗遮罩上滚动也一样，背后页面不动。

1. **图标区分**：左侧栏工作区行、侧栏「+」菜单、目录树工作区 chip 与分组头、设置页卡片与两个创建按钮、「添加工作区」弹窗三个页签——联动工作区统一是「双链环」，远程工作区统一是「显示器 + 出链箭头」，本地工作区仍是文件夹。
2. **悬停预览卡片**：把鼠标停在左侧栏工作区行上，弹出的信息卡里依次是「名称 / SSH 主机 · 连接状态 / 目录 / 创建于」——第二行把主机名与状态合在一起（形如 `RTX-PRO-6000-1 · 已连接`），联动工作区与远程工作区都有；连接正常时该行是绿色，在服务器上 `pkill -u <user> sshd` 掉线后变红并显示「连接已断开」。卡片里**不再显示会话数**，也不再出现浏览器原生 `title` 提示。
3. **卡片里的目录**：远程工作区的卡片只显示**远端目录**绝对路径（例如 `/shared_data_ssd1/huangjh/code`，不显示本地占位目录）；联动工作区的卡片显示两行——「远端 …」与「本地 …」两个绝对路径。
4. **断线变红**：让主机断开 SSH（例如在服务器上执行 `pkill -u <user> sshd`，或在网络中断开）→ 左侧栏该工作区行的图标变红（`#f85149`），悬停卡片里的状态行同样变成红色的「连接已断开」。
5. **自动恢复**：再次访问该工作区（打开目录树 / 刷新设置页）→ 连接重建后图标恢复常规颜色，悬停卡片里的状态回到「已连接」。
5b. **状态跟着实际连通性走（0.16.1）**：把鼠标停在某行上让卡片保持打开，然后让该主机掉线（`hosts.credentials { hostId, clear: true }` 丢掉长连接，再把该主机从 `known_hosts.json` 的指纹改坏；或在服务器上 `pkill -u <user> sshd`）→ 最多 6 秒后卡片那一行变成红色的「连接已断开」，**全程不刷新页面**；恢复指纹/主机后随便访问一次该目录，再等 ≤6 秒，同一张还开着的卡片自动回到绿色的「已连接」。
5c. **目录不存在不算断连**：在插件外用 `rm -rf` 删掉某个远程工作区指向的目录，再在设置页点它的「测试连接」→ 卡片给出「远端目录不存在」一类的提示，但 `hosts.status` 里该主机仍是 `connected`，同一台主机上的其它工作区**不会**被标红；对不存在的路径 `fs.stat` / `fs.list` 也只会返回 `FS_NOT_FOUND`，主机状态不变。
5d. **旧错误会过期**：制造一次真实失败（`hosts.status` 里该主机为 `error`）后什么都不做，等 60 秒以上 → `hosts.status` 里它变成 `{ state: 'idle' }`，卡片显示「未连接」而不是一直红着；随后任意一次成功的目录访问会重新写回 `connected`。
6. **命名**：设置左侧导航显示「联动工作区」，页面标题显示「联动&远程工作区」；「添加工作区」弹窗第三个页签显示「远程工作区」。

## 安全、分页与可访问性（0.8.2）

1. **预览链接净化**：在本地或远端放一个 Markdown 文件，内容含 `<a href="jav&#9;ascript:document.title='X'">click</a>` 与 `[example](https://example.com)`；预览后点第一个链接：页面不应跳转、标题不变、DSH 界面不被替换；第二个链接仍指向 `https://example.com`。`vbscript:`、`file:`、`data:text/html`、`data:image/svg+xml` 链接同样应被移除。
2. **大目录分页**：造一个 20 000 项的目录（`1..20000 | % { New-Item -ItemType File "f$_.txt" }`），在目录树展开它：应只出现 500 行和「加载更多（剩余 19500 项）」，页面不卡顿、可滚动、可点其他文件；点「加载更多」追加 500 行并更新剩余计数，滚到底部后可继续加载。

5. **大文件窥视**：打开一个 >2 GB 的本地文件（只读预览）：应显示「文件过大，仅显示前 512 KB」而不是报错或长时间卡住；内存不随文件大小增长。
